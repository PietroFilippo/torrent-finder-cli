# Torrent Finder CLI v0.8.1

Romanized titles are found under the spelling each source uses, and manga
downloads stay together, optionally as folders of pages.

## Titles under every spelling

Sources list a romanized title one way only. `Mahjong Hishoden: Naki no Ryuu`
found nothing: Madokami lists `Hishoden` but its search fails on the colon, Nyaa
and Knaben list `Hishouden`, and the short name everyone uses is `Naki no Ryuu`.

- **Long vowels.** When nothing matches, a romanized long vowel is also searched
  short, in every provider (`Shingeki no Kyoujin` → `Shingeki no Kyojin`,
  `Mahjong Hishouden` → `Mahjong Hishoden`), and a notice says so.
- **AniList names, more often.** The match ignores long vowels and hyphens
  (`Hishou-den`), and the start of a title counts too (`Mahjong Hishoden`),
  unless it only names a franchise. The names searched are the romaji title as
  releases write it, the English title, and short names it contains
  (`Naki no Ryuu`).
- **Anime** now retries under AniList's names too (`Tate no Yusha no Nariagari`
  finds the `Yuusha` releases).
- **Across providers,** every selected provider searches those names.
- **Madokami** retries an empty search without punctuation such as `:`.
- **The right provider label.** Movies & Series also sees anime through Knaben's
  TV category. A release both find is now listed under Anime; likewise FitGirl
  over General Games.

Live, the reported search went from no results to four: two Anime releases,
the Madokami series folder, and a Movies & Series release only Knaben has.
`Mahjong Hishoden` alone finds four too.

## Manga downloads stay together

- **One folder per series.** Picking two or more Madokami files saves them in a
  folder named after the series (`Naki no Ryuu/`, `One Piece/One Piece [Viz]/`,
  `Naki no Ryuu [Raws]/`), not loose among other downloads. A later single file
  joins that folder when it exists. Batch downloads group the same way.
- **Unpack page archives (optional, Off).** Turn it on under **📁 Download
  folder** on the provider screen, or in the Download Method menu. Downloaded
  `.zip`, `.cbz`, `.rar`, `.cbr`, `.7z` and `.cb7` archives that hold only images
  become a folder of pages beside them; the archive is deleted once the pages
  are in place. It covers Madokami files and torrents downloaded in the app
  (aria2c, webtorrent, peerflix).

## Limits

- Unpacking leaves any archive with other content alone (games, software,
  documents), and cannot reach files a torrent client downloads.
- RAR and 7z need a program that reads them: the `tar` built into Windows 10/11
  and macOS, 7-Zip, or UnRAR. Without one, those archives stay packed and the
  summary says why. ZIP and CBZ always work.
- Files already in the download folder are not moved.
- `Shumatsu no Valkyrie` as manga still finds nothing: AniList's manga search
  doesn't list that spelling. `Shojo Shumatsu Ryoko`, where every word may hide
  a long vowel, can't be narrowed down safely.

## Upgrading

Close running Torrent Finder windows, then use a separate terminal:

```shell
pipx upgrade torrent-finder-cli
```

For regular pip installs: `python -m pip install --upgrade torrent-finder-cli`.
Standalone users can replace their executable with the Windows, Linux, or macOS
asset from this release. Source checkouts can use `git pull --ff-only`.

Saved settings carry over; unpacking stays off until you turn it on.

Validation: **684 automated tests**, including the reported searches replayed
from AniList's real answers, mutation checks on every new rule, and real RAR and
7z archives unpacked with Windows' tar and UnRAR.
